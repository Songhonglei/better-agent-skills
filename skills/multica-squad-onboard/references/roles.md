# 项目作用域模板

以下四个小节由辅助脚本读取；只替换 `{project_id}`，其他项目保持原业务规则。模板是接入契约，公共算法及命令细节读取已安装调度 Skill，不在此复制。

## project
仅项目 `{project_id}` 的小队任务使用 `multica-squad-load-balancer`：正式队长按原任务所需能力调用 `plan → dispatch`；执行者先 `verify-worker`、在业务目录保存私有绑定，通过后执行原业务并在自身触发评论的原线程回报。保留原权限、审批、状态、服务端认证和结果验收；已有执行、终态或写入不确定先对账，不自动换人重派。直接指派个人的任务沿用原流程。

## squad
本段仅处理项目 `{project_id}` 的小队任务时适用。核对当前项目负责人、实时小队关系、完整 Issue、触发评论和自己的 task-run；不按名字或固定成员名单猜角色。关系变化或与原授权不符时停止复核。

正式队长只调度与对账；执行成员不递归调度。统一读取已安装 `multica-squad-load-balancer` 的 SKILL.md，使用真实安装路径及自身 CLI/run 身份，不复制脚本、不写死 profile、服务器或成员。只有原任务明确要求时才解析工作区 Skill UUID / member-role；先满足能力再比较负载，plan 和 dispatch 条件相同。

公共 dispatch 已发布派单 mention 并记录 activity，禁止再手工补发。保持原小队 assignee，不另建子 Issue。已有执行、完成、失败、派单记录或写入结果不确定时先核对评论、runs、业务结果和副作用；no_action 不重派，failed 报告卡点，不自动换人或删除私有意图文件绕过对账。致谢、已交付、等待人工不派单；续跑走原业务受控机制。

成员先通过公共 verify-worker，并在 Skill 安装目录外的业务目录保存私有绑定，再执行业务；校验不代替原服务端 claim/回调、业务权限和审批。历史无公共标记的委派先对账并沿用原业务校验，不伪造标记。使用自身 run，在自身触发评论原线程回报真实结果；run completed 不等于业务成功。保留原业务输出、权限、审批、状态和幂等规则。

## leader
本段仅处理项目 `{project_id}` 的小队任务时适用，其他项目遵循各自规则。仅当自身为该项目负责人且是当前 Issue 唯一活跃正式 is_leader_task 队长 run 时承担队长职责；身份不符停止复核，不自动兼任执行者。

只核验授权、调度、对账和协调回报，不代做该小队任务的业务。读取已安装 `multica-squad-load-balancer` 的 SKILL.md，在真实队长环境使用自身 MULTICA_TASK_ID/MULTICA_AGENT_ID，依次调用 plan → dispatch。原任务要求特定技能或角色时，从当前工作区唯一解析能力条件，两个命令使用相同参数；缺失、歧义或无权限时停止，不空条件派单。无专业要求时不凭空增加条件。

不写手工选人算法，不固定成员，不提高容量。dispatch 已发 mention/记录 activity，不再补发。保持小队 assignee，不建子 Issue。已有执行、完成、失败、派单记录或写入不确定先对账；不自动换人、不删除私有意图文件绕过保护，不因致谢或自动唤醒重派。要求成员先 verify-worker、保存业务目录私有绑定，再执行原业务并在原线程回报。保留原权限、审批、状态、服务端认证、结果验收与受控续跑规则。

## worker
本段仅处理项目 `{project_id}` 的小队任务时适用，其他项目遵循各自规则。只接受已核验正式队长明确委派给自身的任务；自身须为该项目实时小队非队长成员，不得调用 plan/dispatch、递归调度或自动转为队长；关系或身份变化时停止复核。

读取完整 Issue、附件、触发评论和自身 run；优先使用真实 MULTICA_TASK_ID/MULTICA_AGENT_ID，缺失时仅唯一核验自身与当前 Issue，不取“最新 run”或他人身份。在安装依赖、准备目标及任何业务操作之前，读取已安装 `multica-squad-load-balancer` 的 SKILL.md，调用真实安装目录的 verify-worker，并指定业务目录中的私有 binding-file，父目录须存在。

仅 verified 后执行业务；绑定放在 Skill 安装目录外，不覆盖不同身份绑定。历史委派缺少公共标记时先对账并走原业务校验，不伪造标记或绑定。公共校验不授予业务权限，不替代服务端 claim/回调与审批。校验失败停止并报告，不换人、不补发 mention。

使用自身 run 执行原已授权业务并在自身触发评论原线程回报真实结果。已有执行、结果、失败或写入不确定先对账，不自行重试或请求自动换人。保持原小队 assignee，不建子 Issue；保留原业务权限、审批、状态、输出、幂等和结果验收规则，不将 run completed 当作业务成功。
