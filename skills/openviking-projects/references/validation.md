# 验证与交付边界

## 本包检查

```sh
python3 <skill>/scripts/selftest.py
python3 <skill>/scripts/selftest.py --native-python /path/to/openviking-venv/bin/python
```

第一条只用标准库和临时目录，检查镜像/离线安装计划、安装环境隔离、未知参数拒绝、无 Git 同步、策略预检、全局配置原子写入、拒绝覆盖、凭据配置、源码固定 commit 与路径安全。第二条复用给定解释器中已有的 0.5.0 依赖，在干净状态目录启动本机假模型与独立服务；不访问真实模型、不更改原有项目或服务、不装系统任务。`--report /local/result.json` 可将两类结果保存为 JSON。

对新操作系统仍应执行一次真实安装，确认匹配 wheel 与原生二进制。不能把同一台机器的临时目录测试宣称为另一 OS 测试。

## 每项目验收

1. 元数据、白名单/选区、索引量与排除范围可审阅；配置不含其他电脑用户名和凭据。
2. doctor --probe-models 分别通过摘要与 embedding；检查实际向量长度。服务 ready 通过。
3. dry-run 展示实际变化；首次完成后逐份 canonical source SHA256 一致，task 状态与持久回执一致。
4. 使用项目自己的问题清单（建议 6–12 道），真实 find 后 read，核对事实和来源 URI；默认前三条不够再请求八条，记录结果而不是调答案凑分。
5. verify 命令检查真实 STDIO、只读工具、显式工作区、预算、分页、错误快照和跨 scope 拒绝。--contains 应提供项目实际事实；不加时只是检索可用性测试。
6. 有两个以上项目时验证 code/workspace 不匹配与交叉 URI 被拒绝。独立账号另测原生 API 跨账号读取；共享账号应明确“没有原生账号隔离”。
7. 对一份非业务维护文档做有意义的小更新，确认只有一份导入；再无变更同步，确认 unchanged 且没有新增 task。不要为验证修改生产业务文件。
8. 通过后才启用该项目调度。最后在目标 Codex 新会话真正调用一次工具；这一步没有做就明确标注。

## 故障判断

- 账号登录成功但 embedding 403：分别检查模型绑定与权限，不替用户换另一个未授权模型。
- 任务 completed 但原文哈希不一致：看 canonical 路径与 parser 布局，检查是否 Markdown 分片。不能只接受“已导入”。
- 初次目录导入 no-split 与单文件增量布局不同：使用本包的每资料目录暂存结构，且不要把既有 layout 配置改了继续重提。已有数据先审阅、备份并验证自有范围再迁移。
- MCP 进程启动但没有结果：核对 runtime root、客户端环境、工作区信任、tiktoken cache 与 ready，再用真实协议验收。
- 当前文件已变：拒绝使用旧快照是正常保护，先同步或本地 read；相同快照下续页必须带两个偏移和 fingerprint。
- 超五份变化、required_json 不满足、CURRENT 与交付字段冲突、实现指纹变更：保留现场，核对资料，不绕过校验。
- 协议通过而 GUI 未见工具：重新加载工作区/新开会话；不要宣称原生会话已经调用成功。

## 收益怎么量

记录首轮命中、回退次数、工具输出 token、任务总 token、耗时与用户纠正。首次整理/建索引的摘要与向量 token 单独算；重复摘要、全量库误导入和每天索引不变文件都计入成本。工具 JSON 的低预算不是整任务 token 节省率，录制题命中不是最终回答准确率。真实对照验证没有授权时不启动额外模型会话。
